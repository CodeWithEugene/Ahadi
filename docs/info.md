## 7. Our Track In Full: Track 02, Global Payouts And Prize Transparency

Verbatim: snapshot §3. Key lines:

- **Headline:** "Build an Omega agent that decides who gets paid from a prize fund, routes the payouts, and keeps a public ledger anyone can check."
- **User:** "BASIX.MARKET runs hackathons and buildathons with builders across **Lisbon, Nairobi and Chennai**. Winners are judged, placed and paid. As events grow, organisers need prize funds that are transparent and payouts that reach people on different continents reliably."
- **Problem:** "Prize funds are usually **a spreadsheet and a promise**. Participants cannot see how much was received, how much was paid, what fees went where, or what was carried forward. Cross-border payouts **fail, duplicate, or get stuck, and nobody can trace why**."
- **Build, part 1, payout coordinator:** "an Omega agent that applies a published funding rule, proposes payouts, waits for organiser approval, then sends them on Stellar testnet."
- **Build, part 2, public prize-fund ledger:** "a page or feed showing funds received, paid, fees and the reserve carried to the next event, each line linked to a receipt."
- **Tools named:** Raven (Stellar dev help), Stellar testnet, the ledger store, a simulated NEAR Intents quote ("NEAR Intents has no testnet").
- **Omega's role:** "Payout coordinator that applies the rule, proposes, and executes only after approval." **Memory and reasoning:** "Remembers every request and payout; reasons over the funding rule; detects duplicates and failures."
- **Example funding rule:** "Release funds in proportion to eligible teams. 20 eligible teams out of a 50-team target is 40%. A $1,700 fund then gives $680 for awards and $1,020 reserved for the next event, before fees. **Publish the rule before registration.**"
- **Demo script (3 min):** (1) published rule: target, eligible count, cutoff, organiser attestation; (2) agent proposes payouts: recipient, asset, quote and fees; organiser approves; (3) payouts settle on testnet, each on the ledger with a receipt; (4) a duplicate request and a failing one, both handled and recorded; (5) reserve carried forward to the next event.
- **Showcase checklist (our acceptance tests):**
  - [ ] Funding rule published and recorded
  - [ ] Approval before any transfer
  - [ ] Every payout linked to a receipt on the ledger
  - [ ] Failed and duplicate requests handled
  - [ ] Carry-forward to the next event traceable
- **Boundaries:** "Testnet and simulation only. No live funds, no real wallet keys in your repository or on screen."
- **Stretch ideas:** payouts to people without a wallet yet; refunds; a public audit view for participants.
- **HackMeridian note:** "HackMeridian runs 25–26 October in Lisbon. If you plan a separate entry there, document your architecture, findings and tests now, and record your baseline."
- **Best for:** "Builders comfortable with payments and ledgers."

**The example rule is BASIX's real history.** Hackathon 1: $1,700 pool for 50 teams, fewer than half qualified, six teams paid, $1,000 carried forward. Hackathon 2: a $560 pool taken from that $1,000, with a planned split of USD 170 / 140 / 110 / 70 / 70 (hackathon 2 pack, recorded in `../../Sawa/docs/info.md` §11); it is still in judging. Eugene's Mizani took 1st place in hackathon 1 (basix.market "Our Winners"), from Nairobi. **We are building for a user we have been.** (How that prize was paid is for Eugene to tell; nothing about it is assumed here.)

## 18. The Technology: Omega, MeTTa, PeTTa, Stellar, Raven, NEAR Intents

Short version; details in [research.md](research.md) and [research-notes/](research-notes/).

- **Omega** (`singnet/Omega`): published image `singularitynet/omega:latest` = **v0.1.20** (6 Oct 2026; 7.39 GB on disk, arm64 and amd64); `main` is ahead (commit `63a7826`, 22 Oct) and switched to **native LLM tool calling** on 14 Oct (PR #358). A neural-symbolic agent loop in MeTTa on **PeTTa** (MeTTa on SWI-Prolog) that talks over **one channel per process** (IRC, Telegram, Slack, Mattermost, or a **websocket** channel where Omega connects as a client to a server we own), calls an LLM (Anthropic default; OpenAI, OpenRouter, **ASI:One**, **ASI Cloud**, any OpenAI-compatible API), adds tools through plugins (`add-skill` in MeTTa, Python via `py-call`), keeps long-term memory (`remember` / `query` in ChromaDB, plus the episodic `history.metta`, both in a Docker volume that **survived a restart in our test**), and reasons with NAL (`|-`) and PLN (`|~`). **It has no HTTP API and no web UI.** API keys never reach the agent process (an internal proxy injects them). **We ran the real loop end to end in Docker on this Mac on 23 Oct** with a stand-in LLM, a custom plugin and memory recall. Full notes and gotchas: [research-notes/omega-framework.md](research-notes/omega-framework.md).
- **MeTTa**: the language of the Hyperon stack; knowledge as atoms, reasoning by pattern matching and rewriting.
- **Stellar testnet**: Horizon `https://horizon-testnet.stellar.org` (v30, protocol 29), Friendbot funding, ~5 s ledgers, 100-stroop base fee, **next testnet reset 16 Dec 2026** (so receipts made today stay live through judging). JS SDK `@stellar/stellar-sdk@17.3.0`. VERIFIED 23 Oct.
- **Raven**: the Stellar Development Foundation's remote **MCP server** for AI agents (`stellar-experimental/stellar-raven`), tools `search` (docs, ecosystem data, skills) and `execute` (sandboxed JS, no network). It is **dev help, not a payment rail**. VERIFIED.
- **NEAR Intents 1Click API**: `POST https://1click.chaindefuser.com/v0/quote` with `dry: true` returns a signed quote without a deposit address; no API key needed (0.25% extra fee without JWT); supports XLM and USDC on Stellar; validation runs against Stellar **mainnet**, so testnet addresses fail and the simulation uses a recorded fixture or a mainnet placeholder. VERIFIED by two live dry quotes on 23 Oct.

## 22. Glossary

| Term | Meaning |
|---|---|
| **Funding rule** | The published formula that decides how much of a prize fund is released for awards and how much is reserved, e.g. release = eligible teams ÷ target teams |
| **Eligible team** | A team whose submission met every qualifying requirement before the cutoff |
| **Cutoff** | The moment after which eligibility is frozen |
| **Attestation** | The organiser's signed statement of the eligible count and the rule version |
| **Carry-forward (reserve)** | The unreleased part of the fund moved to the next event's fund |
| **Receipt** | A Stellar testnet transaction anyone can open on an explorer, whose memo links it to one ledger line |
| **Testnet** | Stellar's public test network; its coins have no value; reset roughly quarterly (next 16 Dec 2026) |
| **Friendbot** | The testnet faucet that funds a new account with 10,000 test XLM |
| **Trustline** | A Stellar account's opt-in to hold a non-native asset |
| **Claimable balance** | A payment parked on the ledger that a named recipient can claim later, e.g. once they have a wallet |
| **Multisig / threshold** | Stellar accounts can require signatures whose weights add up to a threshold; used to require both the agent and the organiser |
| **Memo** | A short field on a Stellar transaction (up to 32 bytes as a hash) used to link it to a request |
| **Dry quote** | A NEAR Intents quote request with `dry: true`: prices and fees, no deposit address, no funds move |
| **Raven** | Stellar's MCP server for AI coding agents (docs, ecosystem data, sandboxed code) |
| **Omega skill** | A tool the Omega agent can call, declared in MeTTa, optionally backed by Python |
| **NAL / PLN** | Non-Axiomatic Logic / Probabilistic Logic Networks: Omega's uncertain-reasoning engines |
| **EAT / WEST** | East Africa Time (UTC+3) / Western European Summer Time (UTC+1) |
